# Human LLM Gateway 实施路线图

本文件是项目进度的唯一事实来源。2026-09-05 收口结论：核心产品功能已实现，
本次补齐受邀试用所需的运行修复与运维基础。不能把本地测试通过等同于真实部署验收，
也不再宣称全部规划里程碑已结项。产品规则仍以 AGENTS.md 和 docs 中的契约为准。

## 交付范围

- 面向单实例、邀请码注册的小规模使用，不支持多个 worker 或多副本共享数据库。
- 三种推理协议：OpenAI Chat Completions、OpenAI Responses、Anthropic Messages。
- API Key 决定用户、入口、策略和有效 Fake Model；每用户全部 Key 共用 10 个活动名额。
- Fake Model 只作为对外身份；真实上游、IM 连接和用户凭据保持归属隔离。
- Web 和 IM 使用同一规范化回复及工具校验；首个有效提交获胜，网关不执行工具。
- 新库直接按目标 Schema 创建；旧数据库不提供迁移或兼容承诺。

## M12–M14 已实现的关键行为

- 删除工具沙箱、执行服务和前端工具执行页面；只传递调用方声明的工具调用。
- Web/IM 提交都校验工具名称与已声明参数结构，生成稳定调用 ID，网关不执行工具。
- Web 工作台提供工具草稿和结构化预览；提交结果不可撤销或覆盖。
- 服务端生成 trace_id，并关联请求任务、LLM/IM 处理、应用与审计日志。
- 日志异步批量落库，管理台按时间、级别、分类、事件和 trace 查询并脱敏展示。
- 连接删除检查 Key 引用；网关自签 IM Token 创建/轮换时仅展示一次。
- 统一三协议 token 估算、usage 和 SSE 序列；原始请求单独完整保存。
- 高频运行记录按周清理；请求任务和正式草稿保留。
- 统一回复收件箱、未读状态、按需加载的完整上下文、草稿乐观锁与版本冲突。
- 工具参数编辑与声明 Schema 对齐；模型分组支持公开/私有和完整分页加载。
- 无可用 LLM 配置时禁用小助手发送入口；失效配置的历史会话只读。

## 2026-09-05 交付修复

- 修复 sweeper 按人工截止时间误杀正在运行的 LLM fallback；声明与上游预算分开。
- 为流式和非流式转发增加总时长上限，防止单次 I/O 超时无法限制持续生成。
- 跨协议参数不能等价转换时，三协议的直转与 fallback 都返回 400 并释放名额。
- Chat system 内容块保持结构；追加身份指令时不再把数组变成字符串。
- 关闭后台清理时等待数据库线程完成，避免取消协程后线程仍访问数据库。
- 移除启动时自动补旧列的兼容分支；不匹配的库只读拒绝，不静默修改。
- API Key 仅创建时返回明文，列表、详情和修改响应只包含前缀；新 Key 不保存可逆密文。
- IM 工具回复复用 Web 的规范化校验，替代无条件拒绝。
- 修复控制台和任务筛选的手机横向溢出，弹窗/抽屉增加焦点约束与关闭后焦点恢复。
- 补齐部署、备份、监控、生命周期清理与 CI，并纠正 README 与进度记录的完成声明。
