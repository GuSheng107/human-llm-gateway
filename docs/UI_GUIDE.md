# Human LLM Gateway 前端与 UI 规范

> 文档状态：M1 目标 UI 基线
>
> 技术栈固定为 React 19、TypeScript strict、Vite、React Router 和 Tailwind CSS 4。RuoYi 仅作为浅色后台的信息架构与视觉密度参考，不引入 Vue、Element UI 或其组件代码。

## 1. 体验目标

管理后台应该让普通用户快速完成三件事：

1. 建立自己的 IM 连接。
2. 创建 API Key，并明确外部可见模型和回复策略。
3. 在 Web 或 IM 中及时处理任务。

管理员的主要任务是初始化、治理、排障和审计，而不是代替用户操作。任何页面都不能让管理员读取用户 Secret、二维码、完整 Key 或替用户回复。

## 2. 视觉方向

- 使用清晰、克制、偏业务后台的浅色风格。
- 页面背景为浅灰，导航、卡片、表格和抽屉使用白色表面。
- 主色为中等蓝色，状态色只用于表达状态和风险。
- 参考 RuoYi 的紧凑布局、清晰筛选区和表格操作，但减少过重边框与密集按钮。
- 禁止使用大面积纯黑、深灰页面背景、霓虹渐变、玻璃拟态和低对比文字。
- 连接器平台图标可以有品牌色，不能让整张页面变成品牌色块。

排版建议：

| 用途 | 规格 |
| --- | --- |
| 页面标题 | 20px / 28px，600 |
| 卡片标题 | 16px / 24px，600 |
| 正文 | 14px / 22px，400 |
| 辅助文字 | 13px / 20px，400 |

| 等宽数据 | 系统等宽字体，API Key、模型 ID、任务 ID 使用 |

间距以 4px 为基础单位。页面主间距 16-24px，卡片内边距 16-20px，表格行高约 44px。不要用巨大留白模拟营销站。

## 4. 应用框架

### 4.1 桌面布局

- 左侧导航：展开 220px，折叠 64px；白色背景和右边框。
- 顶栏：高度 52-56px；包含面包屑、连接/任务提示、用户菜单。
- 主内容：浅灰背景，内部最大宽度不强制锁死，默认 20px 内边距。
- 全局小助手：右下角入口，展开后为右侧抽屉；切换页面不丢失当前会话。

导航当前项使用浅蓝背景、蓝色文字和左侧 3px 主色标记。未选中项使用深灰文字，hover 使用浅灰或浅蓝，避免深色侧栏。

### 4.2 导航顺序

默认登录后进入“控制台”。一级顺序固定：

1. 控制台
2. 连接 IM
3. API 管理
4. LLM 管理
5. 用户网页回复端
6. 系统设置

推荐路由和二级菜单：

| 一级菜单 | 二级菜单/路由 | 角色 |
| --- | --- | --- |
| 控制台 | `/console` | 全部登录用户 |
| 连接 IM | `/connections` | 全部登录用户 |
| API 管理 | `/api-keys` API Key | 普通用户；管理员只读治理视图 |
| API 管理 | `/fake-models` Fake Model | 普通用户维护私有模型；管理员维护系统模型并治理全部 |
| API 管理 | `/model-groups` 模型分组 | 普通用户，M5 启用 |
| LLM 管理 | `/llm-configs` | 普通用户；管理员只看脱敏治理信息 |
| 用户网页回复端 | `/tasks` | 普通用户；管理员只读任务视图 |
| 系统设置 | `/settings/basic` 基础设置 | 管理员 |
| 系统设置 | `/settings/invitations` 邀请码管理 | 管理员 |
| 系统设置 | `/settings/users` 用户管理 | 管理员 |
| 系统设置 | `/settings/account` 账号设置 | 全部登录用户 |

角色不可用的菜单不渲染。直接访问受限路由时显示 403 页面，不只依赖前端隐藏。

`must_change_password=true` 用户登录后强制跳转到独立改密页面（不进入控制台）。改密页面只展示改密表单和退出按钮，隐藏侧栏和主导航。改密成功后恢复完整界面并进入控制台，无需重新登录。受限会话期间除 `/api/auth/me`、`/api/auth/logout`、`/api/account/password` 外的 API 调用返回 403，前端不得在改密页发起其他业务请求。

用户管理页禁用用户前的确认框必须显示将被撤销的会话数、API Key 数和将被终止的活动任务数，并明确该动作会立即中断请求。系统不提供“仅禁止登录但保留 API 调用”的模糊状态。管理员创建或提升不出现在后台 UI，后续管理员由部署 CLI 创建。

## 5. 页面通用结构

列表页按顺序组织：

1. 页面标题、简短说明和主要操作。
2. 可折叠筛选区。
3. 状态或风险提示。
4. 数据表格或空状态。
5. 服务端分页。

示例结构：

```tsx
<PageShell>
  <PageHeader title="连接 IM" description="管理用于接收和回复任务的个人连接">
    <Button>创建连接</Button>
  </PageHeader>
  <FilterPanel>{/* filters */}</FilterPanel>
  <DataCard>{/* table or empty state */}</DataCard>
</PageShell>
```

通用组件放在 `admin/src/components`；领域组件放在对应 `features/<feature>`。页面不得自行复制按钮、弹窗、分页、状态标签和错误提示样式。

## 6. 组件规范

### 6.1 按钮

- 每个页面最多一个视觉主按钮。
- 普通操作使用次级描边或文字按钮。
- 删除、撤销、重置密码等危险动作使用红色并二次确认。
- 表格行操作保持 2-3 个常用文字按钮，其他收入“更多”菜单。
- 禁用按钮同时提供原因 tooltip，不能只改变颜色。

### 6.2 表单

- 标签置于控件上方，必填项明确标识。
- 服务端字段错误映射到对应控件，页面顶部同时显示摘要。
- Secret 使用 password 控件；读取接口不返回值时显示“已配置”，不能显示伪造星号长度。
- 更新 Secret 时提供“保持原值/替换”明确交互，空字符串不承担隐含语义。
- 模型 ID、Base URL、Header JSON 等字段提供示例和即时格式校验。
- 保存期间禁用重复提交，成功后读取服务端最新资源。

### 6.3 表格

- 表头固定，正文左对齐；时间、状态、操作列宽度稳定。
- 长 ID 使用等宽字体、单行省略和复制按钮。
- Secret、完整 Key、Token、二维码和密码永远不进入表格数据。
- 空状态解释“为什么为空”和下一步；不要只显示“暂无数据”。
- 加载使用骨架或表格占位，不在页面中央只放旋转图标。

### 6.4 弹窗与抽屉

- 简短确认用 Modal。
- 多字段创建/编辑、任务详情、登录二维码和小助手使用 Drawer。
- Drawer 在 1440px 下建议 520-720px；复杂任务详情可使用约 960px。
- 关闭有未保存修改的编辑器前必须确认。

### 6.5 状态标签

状态必须同时使用文字和颜色：

| 语义 | 颜色 | 示例 |
| --- | --- | --- |
| 正常/在线/完成 | 绿色 | 在线、已完成、已启用 |
| 处理中 | 蓝色 | 启动中、响应中 |
| 等待用户 | 橙色 | 待回复、待扫码、待绑定 |
| 错误/停用 | 红色 | 连接错误、已禁用 |
| 中性/已结束 | 灰色 | 已停止、已撤销、已取消 |

## 7. 连接 IM 页面

连接页面按平台分别展示连接和操作，视觉保持本项目浅色后台风格。

### 7.1 普通用户视图

- 页面顶部只保留“检查状态”，弹窗展示全部连接的检查结果。
- 微信 iLink、企业微信、自定义 HTTP、自定义 Webhook、自定义 WebSocket 各占一行；每个用户在每个平台最多一条连接，不显示数量、添加按钮或连接名称。
- 页面不提供搜索和分页，一次展示全部平台；超出视口时只在内容容器内滚动。
- 微信不显示配置表单；点击“绑定（扫码）”时创建该平台的唯一连接并直接展示二维码，扫码确认后服务端保存参数。
- 企微和通用平台通过“配置”创建或更新连接，Secret 写后不回显；企微提示固定私聊命令 `connect mycom`，通用平台显示对应端点信息。
- 要求绑定的平台未扫码或未绑定时不能启用，点击启用直接进入对应登录或绑定操作。
- 每个平台只提供启用开关、平台操作和删除；不再提供独立的停用按钮，关闭开关即停止连接。

### 7.2 管理员视图

- 不显示“创建连接”、登录、二维码、生成绑定码和修改 Secret 操作。
- 增加所有者列和用户筛选。
- 允许查看非敏感配置摘要、运行状态、健康检查、启动、停止、应用和删除。
- 若操作会中断用户服务，确认框明确连接所有者和受影响 API Key 数量。

### 7.3 状态表达

数据库期望状态和运行时状态并列展示，例如“期望运行 / 当前认证失败”。错误摘要只显示脱敏原因和最近时间，并提供复制 request ID，而不是输出 SDK 堆栈。

## 8. API Key 与模型权限页面

### 8.1 创建 Key

使用分步或分区表单：

1. 名称。
2. 回复入口：Web 或一个自己的 IM 连接。
3. 回复策略：人工、真实 LLM、人工超时后真实 LLM。
4. 所需 LLM 配置和人工超时。
5. 模型分组预筛（可选）。
6. Fake Model 直接选择（可选）。

模型选择器只显示经过当前模型分组预筛的候选集。没有勾选任何模型时，控件下方必须明确显示：

> 未单独选择模型，将允许当前候选集中的全部有效 Fake Model。

选择后展示“外部 `/v1/models` 将返回 N 个模型”。分组变化导致已选模型不再属于候选集时，前端清除无效选择并要求用户确认；后端仍做最终校验。

### 8.2 Key 明文

创建成功后用一次性结果弹窗展示完整 Key：

- 明确说明关闭后无法再次查看。
- 提供复制按钮和已复制反馈。
- 禁止把完整 Key 写入 URL、浏览器日志、分析事件或持久化状态。
- 关闭后列表只展示前缀和创建时间。

### 8.3 Fake Model 管理

- 普通用户看到系统模型和自己的私有模型；系统模型带“系统”标签且只读。
- 普通用户可创建、编辑、启停和删除自己的私有模型。
- 其他用户私有模型不出现在列表、选择器、搜索建议或数量统计中。
- 管理员可切换“系统模型/用户私有模型”治理视图，后者展示所有者但不能转授给其他用户。
- Fake Model 表单不出现 LLM 配置、真实模型或路由策略字段。

## 9. LLM 配置页面

- 普通用户维护自己的 OpenAI-compatible 或 Anthropic 配置。
- 列表展示名称、协议、Base URL 主机、真实模型、状态和最近测试结果。
- Secret 不回显；LLM 配置不提供自定义请求头。
- “测试连接”使用行级 loading，并显示成功/失败、耗时和脱敏原因。
- 删除被 API Key 使用的配置时展示引用关系并阻止操作。
- 管理员只查看所有者和脱敏元数据，不显示创建按钮、Secret 编辑或代用测试。

“LLM 管理”只管理真实 LLM 配置；Fake Model 属于“API 管理”，页面和术语不能混用。

## 10. 用户网页回复端

### 10.1 任务列表

- 默认优先展示待回复任务，提供协议、Fake Model、API Key、入口、等待时长和状态筛选。
- 10 个活动名额使用清晰计数，例如“活动任务 7 / 10”。
- 接近上限时用橙色提示，达到上限时说明新请求会返回 429。
- 管理员只读列表增加所有者列，不出现回复入口。

### 10.2 任务详情

推荐左右布局：

- 左侧：完整原始请求、规范化消息、tools、协议 Header 摘要。
- 右侧：时间线、草稿和回复编辑器。
- 移动端改为标签页。

回复编辑器分为 reasoning、tool call 列表和最终文本。tool arguments 使用 JSON 编辑器和即时校验；页面持续提示“仅模拟返回，系统不会执行工具”。Web 表单、保存的 `task_drafts` 和 IM DSL 解析结果必须使用同一个 ReplyDraft JSON Schema，不能分别维护字段映射。

真实 LLM 手动生成结果进入可编辑草稿，按钮文案使用“生成草稿”，不能使用“自动回复”。提交前提供协议响应预览和最终确认；用户确认后才进入 Fake 回复流程。提交成功后不提供撤销、回退或再次提交按钮。

Web 与 IM 竞争时，首个有效提交后立即把页面改为只读结果；晚到回复显示“任务已由另一入口完成”，不得覆盖编辑器中的已接受结果。

## 11. 全局 Web 小助手

- 登录后入口始终可见，但不能遮挡表格分页和主要操作。
- 展开抽屉显示会话列表、LLM 配置选择、当前页面上下文摘要和输入框。
- 页面上下文由 feature 显式提供，用户可在发送前展开预览。每次发送只使用当前浏览器标签页的当前路由、当前选中资源和当前未提交编辑内容。
- 切换路由或选择会立即替换待发送上下文；切回任务页面时重新读取当前任务和编辑器状态，不恢复旧页面的待发送快照。
- 历史消息保留发送时的脱敏上下文摘要和版本，不把多个页面上下文自动拼接到新消息。
- 密码、完整 Key、Token、Secret、Cookie 和连接凭据以“已过滤敏感字段”提示替代。
- 生成内容可以插入当前任务编辑器，但不能直接提交任务。
- 会话删除必须确认，删除后立即从侧栏消失。
- 第一阶段不渲染或执行任意系统 tool call；上游输出中的工具结构按普通文本/不可执行建议处理。

## 12. 反馈、错误和可恢复性

- API 全局错误通知包含用户可理解的消息和可复制 request ID。
- 字段校验错误放在控件附近；权限错误跳转 403；登录过期清除状态并回登录页。
- 429 活动任务上限明确显示当前 10/10，但对外推理错误不暴露人工流程。
- 乐观更新只用于易回滚的启停动作；创建、删除、回复提交使用服务端确认结果。
- 列表筛选、页码和排序写入 URL 查询参数，刷新、前进和后退保持页面状态。
- 网络重试不得重复创建 Key、重复提交回复或重复触发真实 LLM；写操作使用防重复状态和服务端幂等规则。

## 13. 响应式和无障碍

必须由用户最终验收 1440px、1024px、390px，开发阶段先满足：

- 1440px：完整侧栏、筛选区和表格。
- 1024px：侧栏可折叠，次要表格列隐藏到详情。
- 390px：抽屉全屏、表格转卡片或横向滚动、底部操作区固定但不遮内容。
- 所有交互可使用键盘，焦点样式清晰。
- 图标按钮必须有可访问名称，表单有 label，错误与控件关联。
- 正文和背景对比度至少满足 WCAG AA；状态不能只靠颜色。
- Modal/Drawer 打开后管理焦点，关闭后返回触发元素。
- 遵循 `prefers-reduced-motion`，不使用影响任务处理的长动画。

## 14. 前端代码组织

```text
admin/src/
├── api/                 # HTTP 客户端、错误转换、各领域 API
├── components/          # PageShell、Button、Table、Modal 等通用组件
├── features/
│   ├── auth/
│   ├── connections/
│   ├── api-keys/
│   ├── fake-models/
│   ├── llm-configs/
│   ├── tasks/
│   ├── assistant/
│   └── settings/
├── layouts/             # 后台框架、导航和权限菜单
├── routes/              # 路由声明和守卫
├── types/               # 跨领域基础类型；领域类型优先就近放置
└── styles/              # Tailwind 入口和语义 Token
```

规则：

- 组件不直接拼接 API URL；统一走 `api/`。
- 后端 Schema 的 TypeScript 类型在一个位置定义，不在页面复制。
- 页面权限来自 `/api/auth/me` 的 capability，不能散落角色字符串判断。
- 环境相关 URL、超时和分页默认值集中配置。
- 使用 React Router 管理导航，不用手写 `window.location`。
- 保持 TypeScript strict，不用 `any` 绕过接口变化。

## 15. 禁止模式

- 大面积深色/黑色背景或低对比灰字。
- 在 UI 中把 Fake Model 称为真实模型、Provider 或 Route。
- 把用户 LLM 配置放进 Fake Model 表单。
- 管理员页面出现“替用户回复”、Secret、二维码或完整 Key。
- 只在前端校验模型所有权、连接所有权或任务状态。
- Key 未选择模型时显示“无权限”；其真实语义是允许候选集全部模型。
- 提供回复提交成功后的撤销、回退或覆盖入口。
- 变更模型分组后静默保留越界的 Key 模型选择。
- 使用浏览器本地存储保存密码、完整 API Key、LLM Secret 或 IM 配置。
- 用颜色作为唯一状态信息。
- 每个页面各写一套按钮、表格、弹窗和 toast。

## 16. 页面完成定义

一个页面只有同时满足以下条件才算完成：

- 权限、加载、空数据、错误、成功和并发冲突状态完整。
- Secret 和所有者边界通过接口与前端双重检查。
- 复用语义 Token 和通用组件，浅色风格一致。
- URL 可刷新、可前进后退，默认页面仍是控制台。
- 键盘和窄屏可操作。
- API 类型、测试和构建通过。
- 实际视觉由用户验收；开发者不能仅凭构建成功宣称页面验收完成。
