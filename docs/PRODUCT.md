# Human LLM Gateway 产品定义

> 文档状态：已部署版本产品定义
>
> 适用范围：当前线上产品行为、角色边界和不可破坏约束。若产品、API、数据库或 UI 行为发生变化，必须同步更新对应事实来源和 `docs/ROADMAP.md`。
> 术语约定：对外展示的模型统一称为 **Fake Model**；用户配置的真实上游统一称为 **LLM 配置**。
> 许可证：本项目采用 AGPL-3.0-only，完整文本见仓库根目录 `LICENSE`。AGPL-3.0 section 13 要求任何对程序修改并通过计算机网络让用户与其修改版远程交互者，向这些远程交互用户提供获取对应源码的机会；本项目借此对网络部署施加 copyleft 约束。AGPL 不禁止商业使用或销售，copyleft 约束的是源码开放义务。

## 1. 产品一句话

Human LLM Gateway 是一个对外兼容真实 LLM API、对内允许用户通过 Web 或自己的 IM 亲自生成回复的多人网关；用户也可以把请求转发到自己配置的真实 LLM，再将结果伪装成调用方指定的 Fake Model 返回。

## 2. 产品目标

系统需要同时满足以下目标：

1. 外部调用方像调用普通 LLM 平台一样使用 API Key、模型目录、非流式响应和流式响应。
2. 用户在线时，可以在 Web 或绑定的 IM 中人工完成 reasoning、tool call 和最终文本。
3. 人工回复先完整提交并持久化，再由系统按目标协议生成非流式结果或伪流式事件。
4. 用户可配置真实 LLM，用于生成可编辑草稿、直接转发或人工超时后的降级转发。
5. Fake Model 只代表对外身份，不与某个真实供应商或真实模型绑定。
6. 多用户、API Key、IM 连接、LLM 配置和任务严格按所有者隔离。
7. 用户可以使用调用方声明的 tool；若通过命令类 tool 执行危险指令，相关风险和后果由用户自行承担，开发者不承担责任。

## 3. 非目标

当前产品不承诺：

- 复刻真实模型内部的思考过程；reasoning 只是用户或上游生成的响应内容。
- 保证文字内容绝不暴露真实上游身份；系统只提供身份提示和协议字段改写，文本伪装属于尽力而为。
- 自动执行调用方提交的 tool 定义或 tool call。
- 当前部署按产品、架构、API、数据库和 UI 契约运行。
- 将 IM 作为面向外部客户的客服机器人；IM 是系统用户接收任务和提交 Fake Agent 回复的操作入口。

## 4. 角色与资源所有权

### 4.1 角色

| 角色 | 定义 |
| --- | --- |
| 部署者 | 部署并首次启动系统的人，通常也是第一个管理员。 |
| 管理员 | 管理全局配置、用户、邀请码、系统 Fake Model 和审计，并治理全部用户资源。 |
| 用户 | 通过邀请码注册或由管理员创建，维护自己的 IM、API Key 和 LLM 配置并处理自己的任务。 |
| 外部调用方 | 持有某个 API Key，通过三种兼容协议调用系统；不是管理后台用户。 |

第一个管理员由部署环境初始化；后续管理员只能通过受控 CLI 创建（`uv run python -m app.cli admin create ...`，交互式用 `getpass` 隐藏输入，禁止 `--password` 明文参数；自动化用 `--password-stdin --yes`，或用 `--generate-password --yes` 由系统生成满足策略的临时密码——两者互斥，明文只在 stdout 显示一次）。后台不提供创建、提升或转让管理员权限的 API，且系统必须始终保留至少一个有效管理员。

### 4.2 密码与受限会话

密码策略（注册、修改密码、管理员重置、CLI 创建和初始化环境变量统一适用）：

- 最少 10 个 Unicode code points，最大支持至少 128；必须同时包含英文字母（ASCII）、数字、符号（ASCII 可打印标点）三类。
- 输入按 NFC 归一化后哈希；允许空格和 Unicode 字符，但二者不参与三类复杂度判定，仅计入长度。
- 拒绝常见弱密码、与用户名相同或近似、明显部署默认词的 blocklist。
- 存储使用 Argon2id（`m=19456 KiB`、`t=2`、`p=1`）的 PHC 编码字符串；登录成功且参数低于当前策略时同流程重新哈希。不使用 bcrypt。
- 初始化环境变量 `ADMIN_PASSWORD` 不满足策略时启动失败，不得降级为警告后继续。

`must_change_password=true` 的用户（环境变量初始化的首个管理员、使用系统生成临时密码的 CLI 创建管理员、被管理员重置为临时密码的用户）登录成功后获得受限会话：

- 仅允许 `GET /api/auth/me`、`POST /api/auth/logout`、`POST /api/account/password`；其余 `/api/*` 返回 403。
- 前端登录后直接重定向到强制改密页面；改密成功后 `must_change_password` 置 false，会话立即恢复完整权限，无需重新登录。

### 4.3 权限矩阵

| 能力 | 管理员 | 资源所有者 | 外部调用方 |
| --- | --- | --- | --- |
| 签发、撤销、删除邀请码 | 是 | 否 | 否 |
| 创建、启停、重置普通用户 | 是 | 否 | 否 |
| 创建和绑定 IM 连接 | 否 | 是 | 否 |
| 查看所有 IM 连接的非敏感状态 | 是 | 仅自己的 | 否 |
| 启停、检查、删除 IM 连接 | 所有用户的 | 仅自己的 | 否 |
| 查看 IM Secret、Token、二维码 | 否 | 仅在必要交互中查看自己的临时信息 | 否 |
| 创建 API Key | 否 | 是 | 否 |
| 查看 API Key 明文 | 否 | 仅创建时一次 | 使用已有 Key |
| 维护 LLM 配置 | 否 | 是 | 否 |
| 查看 LLM Secret | 否 | 创建/替换时输入，不回显 | 否 |
| 创建和维护系统 Fake Model | 是 | 否 | 通过 `/v1/models` 查看 Key 可用目录 |
| 创建和维护私有 Fake Model | 治理全部但不能转授给他人 | 仅自己的 | 否 |
| 选择 API Key 可用 Fake Model | 否 | 从自己可见的模型中选择 | 否 |
| 处理任务并提交回复 | 否 | 仅自己的 | 否 |
| 查看任务与审计 | 可查看非敏感全局信息 | 仅自己的 | 仅取得本次 API 响应 |

管理员拥有治理权，不等于拥有用户身份。管理员不得替用户回复，也不得读取用户密码、完整 API Key、LLM Secret、IM Token 或登录二维码。

审计允许管理员知道“谁在何时对哪个资源执行了什么动作以及结果”，例如凭据已轮换；这属于治理能力。审计不得保存或展示请求正文、凭据值、Secret 变更前后值及可用于恢复凭据的材料。

## 5. 统一领域语言

| 术语 | 定义 | 明确不表示 |
| --- | --- | --- |
| Fake Model | 对外公开的模型身份，例如 `gpt-5`；可以是管理员维护的系统模型，也可以是用户私有模型。 | 不绑定真实 LLM，不决定由谁回复。 |
| LLM 配置 | 用户保存的真实上游连接，包括协议、Base URL、密钥和真实模型。 | 不是 Fake Model，也不是全局供应商目录。 |
| API Key | 外部调用凭据，同时决定请求所有者、投递入口和回复策略。 | 不代表单个 Fake Model。 |
| 模型分组 | 用户从自己可见的 Fake Model 中建立的可复用候选集，在 API Key 直接选模型前先筛选一次。 | 不等于 LLM 配置或上游模型列表。 |
| IM 连接 | 用户自己的微信、企微或自定义连接，用于接收任务和提交回复。 | 不是外部客户聊天渠道。 |
| 请求任务 | 一次已通过鉴权、模型和并发校验的外部推理请求。 | 不是 IM 消息本身。 |
| 活动任务 | 已占用用户并发名额且尚未进入终态的请求任务。 | 不包含已完成、失败、超时或取消任务。 |
| 回复草稿 | 尚未提交、可继续编辑的人工或真实 LLM 生成结果。 | 不会自动成为外部响应。 |
| 回复策略 | API Key 的 `human`、`llm` 或 `human_fallback_llm`。 | 不由 Fake Model 决定。 |
| 伪流式 | 完整回复已生成并落库后，再按协议逐块输出。 | 不是真实生成过程。 |
| 上游流式 | 真实 LLM 在生成时直接返回或实时转换的事件流。 | 不需要先完整落库再开始。 |
| Web 小助手 | 全局可见、使用用户 LLM 配置的辅助会话。 | 初期不是自主执行系统操作的 Agent。 |

## 6. 核心产品流程

### 6.1 初始化与入驻

1. 部署者配置环境变量并启动系统。
2. 数据库不存在时，系统创建新结构、管理员账号和默认 Fake Model 目录。
3. 管理员登录后签发邀请码，设置过期时间和最大使用次数；撤销会立即禁止继续使用并保留记录，删除会在已撤销后把记录从普通列表隐藏但继续保留审计和注册来源。
4. 用户使用有效邀请码注册，或由管理员直接创建账号。
5. 邀请码校验失败统一返回明确的 400；消费次数必须在数据库事务中原子更新。

### 6.2 用户准备工作

1. 用户创建并绑定自己的一个或多个 IM 连接；也可以只使用 Web。
2. 用户创建一个或多个 LLM 配置，供草稿、小助手或自动转发选用。
3. 用户创建 API Key，并为 Key 选择：
   - 投递入口：Web 或自己的一个 IM 连接；
   - 回复策略：人工、真实 LLM、人工超时后转真实 LLM；
   - 可选 LLM 配置；
   - 人工超时时间；
   - 可选 Fake Model 分组；
   - 可选一个或多个候选 Fake Model，不选择代表允许候选集中的全部模型。
4. API Key 明文只显示一次，数据库仅保留可验证哈希和安全前缀。

`/v1/models` 与三个推理入口都必须先验证 API Key。系统不提供匿名 Fake Model 目录，因为没有 Key 就无法确定用户私有模型、模型分组和 Key 直接选择结果。

### 6.3 外部请求准入

外部请求按固定顺序处理：

1. 验证协议和 API Key。
2. 确定 API Key 所有者。
3. 计算 Key 的有效模型集合，并检查请求的 Fake Model 是否存在、启用且在集合内。
4. 检查该用户的活动任务总数是否小于固定上限 10。
5. 原子占用一个用户级任务名额并完整保存原始请求。
6. 根据 API Key 的策略和入口进入人工或真实 LLM 流程。

一个用户的所有 API Key 和全部回复策略共享 10 个活动任务名额。即使请求准备转发真实 LLM，也不能绕过该限制。第 11 个请求直接返回目标协议兼容的 429。

### 6.4 人工回复

1. 任务创建后始终出现在所有者的 Web 工作台。
2. 如果 API Key 选择了 IM，系统同时向该连接投递任务；投递失败不影响 Web 可见性。
3. 用户可填写 reasoning、最终文本和多个模拟 tool call，也可保存草稿。IM DSL 解析结果与 Web 编辑器必须生成同一个规范化回复结构。
4. Web 与 IM 均可提交，首个通过条件更新的有效提交获胜。
5. 提交前允许预览、编辑和放弃草稿；首个有效提交成功后不可撤销，晚到提交不能覆盖结果，只记录审计并提示任务已结束。
6. 系统在事务中保存完整回复和事件，任务进入 RESPONSE_READY；此时仍占用活动任务名额，人工提交成功本身不释放名额。
7. 非流式请求一次性返回协议结果；流式请求把已完成结果转换成伪流式事件。任务在开始对外发送时进入 RESPONDING，响应正常结束后进入 COMPLETED 并释放名额；发送过程因取消、用户禁用或失败中断时进入 CANCELLED 或 FAILED 终态并释放名额。名额释放一律以任务进入终态为准，慢速响应在发送完成前不能腾出并发额度。

模拟 tool call 只作为响应内容返回。系统不执行工具，也不等待调用方回传 tool result。调用方后续携带 tool result 的请求被视为一次新的推理请求。

### 6.5 手动生成 LLM 草稿

1. 用户在任务页面选择自己的 LLM 配置并请求生成。
2. 系统将任务原始请求转发给真实 LLM。
3. 生成结果持久化为回复草稿，不完成任务。
4. 用户预览、编辑 reasoning、tool call 和最终文本。
5. 用户手动提交后，才进入与人工回复相同的 Fake 响应流程。

### 6.6 直接转发与人工降级

- `llm`：任务准入后立即使用 API Key 指定的 LLM 配置转发，结果自动返回。
- `human_fallback_llm`：先等待人工回复；超过配置时间且任务仍可处理时，只触发一次真实 LLM 转发。
- 人工超时默认 300 秒，允许范围 10 秒至 30 分钟。
- 自动转发不需要人工预览，但仍受用户级 10 个活动任务上限约束。
- 上游异常或人工失败对外返回通用、协议兼容的错误，不暴露人工、IM、fallback 或内部实现。

### 6.7 全局 Web 小助手

1. 小助手在登录后的管理后台始终可见，跨页面保持会话。
2. 用户选择自己的 LLM 配置。
3. 当前 feature 显式提供经过筛选的页面上下文，不抓取整个 DOM。
4. 密码、完整 Key、Token、Secret 和连接凭据不得发送给真实 LLM。
5. 会话和消息持久化，用户可以删除自己的数据。
6. 第一阶段只生成文本或操作建议，可把内容插入任务回复编辑器。
7. 用户可以使用调用方声明的 tool；若通过命令类 tool 执行危险指令，相关风险和后果由用户自行承担，开发者不承担责任。

每次向小助手发送消息时，只取当前浏览器标签页、当前路由、当前选中资源和当前未提交编辑内容的脱敏上下文快照。切换页面会替换待发送上下文，不自动累积旧页面数据；历史消息保留各自当时已经过滤的快照。

### 6.8 账号与资源停用

- 管理员禁用用户时，系统立即撤销该用户登录会话、停用全部 API Key、终止全部活动任务并幂等释放名额。等待中的 HTTP/SSE 请求只收到通用协议错误，不暴露停用原因。
- 停用或删除 API Key 只阻止新请求；已经完成准入的任务使用创建时快照继续执行。需要紧急终止时应禁用用户或显式取消任务。
- 删除被有效 API Key 或活动任务引用的 LLM 配置返回 409。历史任务保留名称、协议、规范化 Base URL 和真实模型等非敏感快照，但不保留 Secret，也不能用已删除配置重新执行。
- 期望运行的长连接在普通网络故障后自动指数退避重连；进入需要重新认证的状态后停止重试，等待资源所有者重新登录。启动、停止、应用配置和恢复只影响目标连接。

## 7. Fake Model 规则

- 管理员可以创建系统 Fake Model，系统模型对所有用户可见。
- 普通用户可以创建自己的私有 Fake Model；私有模型仅对所有者可见和可用，管理员只在治理视图中查看和管理，不能转授给其他用户。
- 用户只能编辑和删除自己的私有 Fake Model，不能修改系统模型或其他用户模型。
- 同一个 `model_id` 可以分别存在于不同用户的私有目录；若用户私有模型与系统模型同名，该用户的有效目录优先使用私有模型且只展示一个条目。
- API Key 的候选集先取“当前用户可见且启用的模型”；绑定模型分组时，再与组内模型取交集。
- 用户可继续为 API Key 直接选择一个或多个候选模型；显式选择后，只允许所选交集。
- API Key 未直接选择任何模型时，代表允许候选集中的全部模型，而不是无模型可用。
- `/v1/models` 只返回上述规则计算出的 Key 有效模型集合。
- 外部请求可以选择目录中的任意 Fake Model；这不会改变人工所有者或真实 LLM 配置。
- 不存在、停用或不在 Key 有效模型集合内的模型返回协议兼容的 `model_not_found`。
- 所有对外响应中的 `model` 或等价字段都改写为本次请求的 Fake Model。

## 8. 转发保真与身份伪装

### 8.1 同协议转发

同协议转发默认保留调用方提供的完整原始请求，包括 tools、tool choice、消息扩展和未知字段。系统在原有 system 内容之后追加服务端身份指令：

```text
始终以 “{fake_model}” 的身份回答。不得提及真实供应商、真实模型、转发过程或本系统内部实现。
```

服务端身份指令不覆盖或删除调用方内容。真实 LLM 返回后，协议级模型标识必须改写为请求中的 Fake Model。

`previous_response_id` 等在 API 契约中明确列出的网关控制字段属于例外：网关完整保存原始值，验证它只能引用同一 API Key 的历史响应，然后加载历史请求和回复并等价展开为本次上下文。字段被消费或重写必须在转换矩阵中明确，不能假装已经原样透传。

### 8.2 跨协议转发

- 可等价表达的标准消息、reasoning、文本和工具语义应转换。
- 不能等价转换的供应商专有字段不得静默丢弃。
- 发现不可转换字段时，明确返回目标协议兼容的 400。
- 流式上游结果在生成过程中实时转换，不伪装为人工伪流式。

## 9. 错误与隐蔽性

| 场景 | 对外行为 |
| --- | --- |
| 请求体或邀请码不合法 | 400，使用对应 API 的稳定错误结构。 |
| API Key 缺失、无效或停用 | 401。 |
| 用户被管理员禁用 | 新请求返回 401；已准入活动任务终止并返回通用协议错误。 |
| Fake Model 不存在、停用或不可用 | 协议兼容的 `model_not_found`。 |
| 用户已有 10 个活动任务 | 429，不进入任务、IM 或真实 LLM 流程。 |
| 人工等待超时且无可用 fallback | 504，通用 timeout 错误。429 仅保留给真实的并发名额限制，不用于伪装内部故障。 |
| 调用方在任务进入终态前断开 | 任务进入 CANCELLED（`caller_disconnected`）并幂等释放名额；晚到人工回复只记录审计并提示任务已结束。 |
| IM 投递失败 | 任务仍可在 Web 处理，不向调用方暴露 IM。 |
| 上游真实 LLM 失败 | 500 通用协议错误，不暴露供应商 Secret 或内部路由。 |

错误消息不得出现“人工”“真人”“IM”“fallback”“内部路由”等实现细节。

## 10. 发布边界

### 首个可用 MVP（M6 完成）

- 新用户和权限模型。
- 邀请码注册。
- 用户自有 IM 和 API Key。
- 系统 Fake Model、用户私有 Fake Model 和 API Key 模型选择。
- 用户级固定 10 任务并发控制。
- 三种推理入口。
- Web/IM 人工回复、reasoning、假 tool call、非流式和伪流式。

### MVP 后（M7-M14）

- LLM 配置、手动草稿、直接转发和人工降级。
- 全局 Web 小助手。
- 完整浅色管理后台和日志体验。
- 基础部署、日志保留、健康检查和运维交付；当前实例已部署。`/healthz` 只检查进程存活，`/readyz` 只读取启动状态，不检查工具执行状态。

Fake Model 分组属于 M5 的核心模型权限能力。用户可以使用调用方声明的 tool；若通过命令类 tool 执行危险指令，相关风险和后果由用户自行承担，开发者不承担责任。M13 完成 trace 关联日志、IM 归属隔离和高频数据保留；M14 完成统一回复工作台。日志查询统一使用 `/api/logs`，支持 trace、分类、等级、事件模糊筛选和脱敏上下文详情。

## 11. 不可破坏的产品约束

后续每个阶段都必须维持：

1. Fake Model 与真实 LLM 配置解耦。
2. API Key 决定请求所有者；普通用户永远不能访问他人资源。
3. 管理员不能读取用户 Secret，也不能替用户回复。
4. 用户活动任务固定最多 10 个，所有 Key 和策略共享。
5. Fake Model 权限按“用户可见集合 → 可选模型分组 → API Key 可选模型”逐层收窄，任何层都不能扩大上一层权限。
6. 首个有效回复获胜，晚到回复不能覆盖。
7. 首个有效回复提交后不可撤销；IM DSL 与 Web 编辑器共享同一规范化回复结构。
8. 人工伪流式必须在完整回复落库后开始。
9. 调用方声明的工具不由系统执行。
10. 同协议默认保留调用方字段；声明为网关控制的字段必须等价消费或重写，跨协议不得静默丢失语义。
11. 协议响应不暴露真实 LLM、人工流程或内部连接方式。
12. 禁用用户会立即终止活动任务并释放名额。
13. 数据库、服务、API、前端和测试必须保持同一产品契约。
